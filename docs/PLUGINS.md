# 插件说明与作者接口

[文档目录](INDEX.md) · [管理员操作](guide/plugins.md) · [精确能力表](PLUGIN_SUPPORT_MATRIX.md)

## 安装、配置与执行

插件来自程序编译时固定的 `github.com/dingding229/mediatool-plugin` 定义。管理员在内置目录选择、确认权限后创建实例，默认停用。只有明确启用的实例运行；每个实例有独立配置、加密数据、文件和执行身份。

程序不接受源代码、仓库 URL、ZIP、二进制上传或运行期代码下载/编译。界面没有来源、提交或版本选择器。插件界面只能使用与应用锁定依赖一致的本地声明或打包资源，不能加载远程脚本。

定义扩大权限时停止实例，管理员核对新增权限后才能重新启用；确认权限本身不启用。定义不可用时保留配置与数据，禁止继续执行。停用时可以保存 JSON 配置，动态表单、状态页和仪表盘需要已启用实例提供。

## 作者仓库与生命周期

公开 SDK 在插件模块的 `sdk/`，实现位于 `plugins/<id>/`，`registry/` 显式注册元数据与工厂。作者不得导入主程序 `internal`。包初始化不能做 I/O、创建实例或产生其他副作用；目录枚举不执行工厂。

必须实现：

```go
type Plugin interface {
    InitPlugin(context.Context, Config) error
    GetState(context.Context) (bool, error)
    StopService(context.Context) error
}
```

可选接口包括 `NameProvider`、`FormProvider`、`PageProvider`、`APIProvider`、`ServiceProvider`、`CommandProvider`、`DashboardProvider`、`DashboardMetaProvider`、`ModuleProvider`、`ActionProvider` 和工具接口。使用 SDK 定义的参数与返回值，不自行建立不受控网络入口。

API、服务、命令、动作和模块由实际 Go 函数绑定，运行时生成处理器标识；声明的路径、方法、认证、资源和所需权限必须一致。保存配置会更新执行身份，旧处理器不能继续用旧身份写入。

## 宿主调用、数据与权限

- 使用 SDK typed Host 客户端访问经过允许的业务能力，具体方法、scope、读写级别和条件见能力表。
- 每次调用核对当前实例、授权和执行身份；配置/KV 写入使用预期修订号，冲突后读取对照。
- 不提供任意 SQL、数据库连接、Redis 连接、115 Token、临时直链、共享通知令牌或任意网页正文。
- 写调用使用稳定操作标识。超时或结果未知可能已有副作用，应查询原收据，不更换幂等标识重复执行。
- `pending`、`requested`、`unknown` 和完成是不同结果，通知入队不能当作送达，季覆盖不能当作整剧完结。
- 状态和数据保存在 PostgreSQL；实例私有文件位于程序分配的数据目录，不得跨实例或跟随链接逃逸。

## 进程与日志

插件由同一个 app 二进制的插件工作子进程执行，运行环境不含数据库、主密钥和官方授权等秘密。资源限制、进程组回收、崩溃退避和实时撤权共同约束执行；这些机制不把受信 Go 代码变成可安全运行任意恶意代码的环境。

标准输出用于 RPC，普通日志使用标准错误。宿主按插件实例记录有界日志和固定结果信息；不要输出配置、凭据、用户正文或操作密钥。

## 事件与策略

使用 SDK 的 typed 事件与动作上下文。广播只能订阅声明且授权的精确事件；策略链结果按宿主 schema 校验，不能扩大调用者权限、改变媒体身份或替换播放解析。

通知与刷新模块先处理 `offer` 协商，只有宿主发起 `execute` 才可产生外部副作用。执行后不能返回“未开始”诱导重发；未知结果必须保留核对状态。入站命令只接收授权范围内的内容，不得拼接为 Shell 命令。

发现/推荐候选由后台生成缓存，浏览请求不直接驱动插件工作进程；按宿主实际分页和截断标志展示，不接受任意来源 URL。

## 页面、表单、仪表盘和工具

声明式界面按允许的组件和字段渲染；本地 ESM 只能使用打包入口与允许的共享依赖，不通过 eval 或任意动态导入加载代码。插件界面不是获得后台无限权限的入口。

人工工具的描述包含名称、说明、输入格式、所需权限、效果分类和处理器。效果不可低报，写入或危险调用需要管理员确认。输入使用有界 JSON Schema 子集，不支持的关键词不能忽略；不自动转换类型或从网络解析引用。

工具调用限制包括输入 16 KiB、输出 32 KiB、格式声明 8 KiB/8 层/128 节点及有界执行时间。没有 LLM 聊天或自动工具循环。

工作流只运行管理员批准的有界定义，最多 32 步、深度 16；修改后需重新批准。未知或失败步骤不自动重放，也不恢复已发生的外部业务副作用。

外部账号绑定仅提供状态与显式绑定能力，不支持通过插件直接登录管理员账号、签发会话或决定管理员权限。

## 内置插件的使用边界

| 插件 | 用途与保护 |
| --- | --- |
| `hello-go` | 人工查看和调用接口示例，不自动运行业务 |
| `site-checkin` | 站点签到；宿主持有站点认证，缺少成功信息不认定签到完成 |
| `library-refresh-notify` | 合并资产刷新与通知；沿用稳定操作身份，未知请求不重复创建 |
| `seeding-cleanup` | 默认预览；执行及删除文件独立开关，继续核对做种、归属与在途保护 |
| `watch-organize` | 有界目录监测和整理，依赖可靠修改时间，不以文件大小替代静默检测 |
| `wishlist-subscribe` | 公开列表发现；创建需独立启用，唯一匹配也只创建停用订阅 |
| `torrent-assistant` | 下载状态协助；写入与重新检查需独立启用，活跃监控即使不写也可能通知 |

## 构建与分发用法

在插件仓库完成实现与检查后，先发布插件模块，再让主程序锁定该依赖并生成同源清单与界面资源。主程序通过正式 Docker Hub 不可变镜像分发；管理员不能在运行期改变依赖或装入外部代码。

作者命令见[命令参考](CLI_REFERENCE.md)。能力表标记为 `unsupported` 或 N/A 的项目不能据此视为可用功能。
