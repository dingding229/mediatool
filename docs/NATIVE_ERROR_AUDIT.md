# T54 错误处理审计（2026-10-17）

## 范围与规则

- P4的42条仅覆盖当时检查的协议/用户/设置/HTTP包。全仓扫描共433条，其中5条来自未跟踪的本地私有诊断脚本（data/），本组只读，不修改/入仓这些证据。产品目录cmd/internal/migrations/tests共428条，全部纳入处理。
- 验证命令：`go run github.com/kisielk/errcheck@v1.9.0 -ignoretests ./cmd/... ./internal/... ./migrations/... ./tests/...`。没有配置函数级批量排除或忽略整个包；Go测试代码由race/契约/集成验证，私有data脚本不属于产品发布源。
- `cleanup.Close/CloseContext`仅用于只读/描述符释放或重复关闭，调用点带固定理由；不吞主读写/状态转换错误。不会在清理中调用日志存储，避免日志自身锁重入及错误文本携带URL/凭据。
- `cleanup.Rollback`在原操作/Commit结果已确定之后，使用脱离取消、2秒上限的上下文中止事务；pgx在Rollback失败时丢弃底层连接，不将仍有事务的连接返池。已Commit的ErrTxClosed不改变成功结果。
- 主要DB写入、Scan、身份/证据JSON解码错误现在返回上层；无error通道的后台回调记录固定操作名，不记录原始错误/SQL参数，不伪造成功。条件/fenced更新允许0行；插入和需命中单行的现有RowsAffected检查保留。
- 会话级advisory unlock改为检查bool/err；失败时物理丢弃连接，不把持锁连接还池。集成测试模拟失败解锁，并验证新连接可重新取得同一测试锁。
- 备份/恢复写文件Close和日志Close/Clear错误参与主结果；STRM临时清理仅忽略rename后的NotExist，其余清理/根句柄关闭错误加入返回值。只读日志Seek失败先释放句柄再返回。
- HTTP正文已提交后的写出/断连错误停止当前输出，不再追加第二份JSON；CMD报告写出失败返回错误或非零退出。可选截止时间清除不支持时不重启流、不恢复relay/HLS/转码。

## 保留的非故障语义

- Telegram默认连接查询的`pgx.ErrNoRows`表示“未配置外发”，仍写站内消息；其他SQL错误才返回。不能把可选连接缺失误当整个流水线失败。
- `http.ErrNotSupported`清除写期限表示ResponseWriter没有相应套接字控制能力；保留原控制流，其他清除失败显式检查。初始超时/上下文和禁止中转决策没有被放宽。
- 已删除/损坏的搜索缓存身份是cache miss，不作为“可复用身份”；重新走验证后的新搜索。可空显示metadata缺失与无效JSON分开处理。
- 新增测试覆盖事务取消后的有界清理、失败解锁丢弃连接；原流水线/代理/管理路由回归继续跑，不用修改真实授权、媒体或生产数据验证错误处理。
