# 单集元数据与实际多集覆盖

日期：2026-10-10；维持迁移19，不自动修改已有用户媒体。

## Provider范围与校验

TMDB季详情API一次请求取得单集集合，按显式确认的剧集ID/季号/集号选择；检查season_number、episode_number、单集ID、存在的show_id、标题、日期、时长与图片路径。缺集、重复、返回不同身份/季号、异常数据和HTTP失败都明确中止，不拿整剧简介冒充单集，也不补猜缺失集。

- Season 0特殊集合法；空播出日期/时长保持未知，不填当年或0分钟假值。
- 请求包含未来/未知播出日期的明确文件覆盖时不按订阅的“已播集”筛掉。订阅SeasonEpisodes的已播过滤仍独立。
- 单次上限100个明确集号，排序/去重校验；一个季请求不为每集请求一遍。
- 单集集合写入该资产media_identity及NFO意图，写入media_items的整剧metadata剥离episodeDetails，避免某文件覆盖污染同剧其他资产。
- 搜索/确认、身份修正、迁移预览/应用及下载入库使用同一校验边界。只读预览不提交文件/绑定；迁移proof包含NFO内容摘要，Provider内容改变后须重新预览。

官方参考：developer.themoviedb.org/reference/tv-season-details、tv-episode-details。协议/消费者验证单独记录，不把文档字段存在等同真实账号查询成功。

## NFO与命名

单集NFO使用真实单集标题/简介、airdate/year、已知runtime与单集TMDB ID，showtitle仍为整剧标题；共享tvshow.nfo保留整剧ID/简介。

多集只生成一个episodedetails，不拼多个XML根或重复episode标签。标题/简介组合明确覆盖集，runtime仅所有集已知时求和，首集ID作为该NFO的代表身份；完整覆盖保留在DB及STRM命名。没有声称消费者显示全部覆盖或区分任意非连续集合已实际验收。

- 单集：S01E01。
- 明确连续1,2,3：S01E01-E03。
- 明确非连续1,3：S01E01E03，不写范围、不添加不存在的2。
- 所有同文件集必须同季，支持Season 0；输入不变，内部排序。
- 新确认/下载入库以及明确输出迁移采用此规则。旧已入库文件名和播放URI不自动重写，用户选择迁移前仍按既有路径。

参考Emby官方TV-Naming中的multi-episode约定。内部Parser round-trip已验证，真实Emby/设备识别矩阵仍要记录，尤其非连续链不能仅凭字符串测试外推客户端行为。

## 管理界面

选择剧集并填季集后可“预览单集信息”；批量确认时该按钮显示首个文件的预览范围。GET /api/v1/metadata/episodes需要管理员会话，明确tmdbId/season/episodes，最多15秒；重复/未知查询参数拒绝。改变身份/季集或关闭对话框即清空预览，旧异步结果不覆盖新选择。真正提交会再次校验，不把GUI预览当权威事实。

## 证据

隔离HTTP/PG与NFO XML验证：正确/缺失/错误身份、空字段、日期、HTTP失败、稀疏覆盖、资产与整剧隔离、NFO字段/图片数据只作路径保存、确认/迁移不变播放Key。Chrome E2E只读预览/变更清空/无绑定写入。共享Go缓存曾被外部清理导致缺包，最终回归改用项目独立GOCACHE，不清理用户全局缓存。

最终发布/真实TMDB只读查询/STRM原链接与禁止转码回归以episode-metadata-*记录为准。没有自动重写用户NFO，没有把测试标题/影视身份注入正式库。


## 2026-10-11 实际消费者修正

同部署Emby 4.10.1.0的隔离真实扫描证实，E01E03链即使带NFO仍扩为E01–E03。该历史命名不再用于新非连续合集输出；只显示代表首集也会遗漏声明覆盖，因此未采用。现为每个实际声明集号生成完整文件索引，共用原固定链接，不补缺集、不转码或切片；单集/连续范围保持。旧用户输出必须明确预览迁移，不能自动重写。详见EMBY_EPISODE_PROJECTION.md与emby-projected-consumer-matrix.json；该测试仍不是实际客户端解码或真实PT业务验收。
