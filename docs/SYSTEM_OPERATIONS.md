# 系统运维（0.26.0-dev）

入口为“系统运维 → 任务队列”（`/jobs`），不增加容器、守护程序或第二份Compose。

## 已交付

- 管理员只读 `/api/v1/system/operations`：PostgreSQL/Redis有界Ping及延时；主库大小、Go连接池、应用堆内存/goroutine；迁移版本；Worker心跳及20秒在线判定；按队列/状态聚合、过期租约；待处理/失败通知数。
- Cron表：核心协调六字段含秒、站点刷新、订阅全局表达式与各订阅实际到期时间、云盘扫描、插件服务及设置覆盖后的表达式。显示停用、数据库下次到期/最近派发和错误；不能读取时明确报告，绝不以零/健康替代。
- 任务服务端分页和状态/队列/类型/关键词筛选；`GET /api/v1/jobs/browse?page=1&pageSize=25`（最多100条/页），`GET /api/v1/jobs/{id}`完整详情。查询使用绑定参数，详情包含原始payload但不包含租约令牌，全部需管理员会话。
- 保留原有最近100条 `/api/v1/jobs` 和SSE接口，避免中断业务消费者；新页任务5秒、健康状态15秒可见时轮询。
- 复用日志（等级/查询/大小/清理）、PG/Redis只读浏览、通知（投递/重试）、连接总览、插件和系统设置。`system.check`可人工加入队列，任务详情提供证据，不通用重放上传、整理和删除。

## 如何解读

应用堆内存不是主机内存；主机内存/剩余空间继续在总览查看。Worker在线不是所有外部服务健康，也不是调度周期完成的证明；无在线默认Worker会显示告警。Cron下次到期不是预计完成时间，停用项即使保留旧时间也不会派发。核心协调不持久化“下次到期”，显示为“—”，实际表达式与运行代码共享常量。

业务Cron总表最多300条（站点/扫描/订阅），插件最多100个，每插件最多8个服务；完整管理进入相应业务页。快照带采样时间，刷新失败保留旧快照并显示错误，不能视为最新健康状态。

## 部署与安全

- 所有查询受请求超时约束，返回no-store，不执行维护写入、不探测115/PT登录、不创建生产凭据。
- 更新仍由 `scripts/update-server.sh` 做备份、不可变Docker Hub镜像校验及app-only更新。不要在Web中开放shell、Docker socket、任意SQL或一键清卷。
- 自动备份恢复控制台、主机Docker管理与跨主机监控不在本轮范围；保留既有发布备份/回滚方式。

## 永久API凭据

迁移49将所有已存API凭据的expires_at置NULL，新凭据永久有效。摘要、加密token、ID、权限、使用记录及撤销状态不改变。后台移除有效天数输入，`expiresAt`返回null。失效仅由主动撤销/凭据更换等管理动作产生；120次/分钟/凭据和接口权限检查不变。不改变管理员会话、115临时直链与播放授权票据的安全时效。
