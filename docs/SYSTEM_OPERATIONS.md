# 系统运维与维护中心 · 0.27.0-dev / schema50

## 入口与运行方式

“系统运维 → 任务队列 → 备份与维护中心”，地址 `/maintenance`。任务页保留健康/Worker/队列/Cron，维护中心包含备份管理、恢复与回滚、告警、运行趋势和策略。唯一Compose仍只有app/PostgreSQL/Redis；维护Worker在app内，不新增功能容器，不挂Docker Socket，不保存主机SSH私钥。

## 备份及保留

- 镜像内置PostgreSQL18客户端。手动备份或五字段Cron（默认03:00，Asia/Shanghai，默认关闭）进入maintenance专用队列，不阻塞搜索默认队列。
- 从同一PG只读一致性快照导出custom dump与逐表摘要；复制已登记的STRM/NFO/字幕并验证归属摘要。文件缺失、越界、符号链接、手工变更或摘要不符时失败，不伪装完整备份。
- `/data/maintenance/<UUID>`私有目录0700，dump/tar/manifest为0600；文件管理禁止浏览此目录。备份不包含主密钥、115原媒体、qB做种源、Emby/CD2/qB外部卷；这些须独立保管/备份。备份仍含敏感数据库内容，禁止提交GitHub或公开日志。
- 下载由管理员会话鉴权，以tar包含manifest.json/database.dump/outputs.tar。摘要损坏拒绝演练/恢复；不支持任意路径文件上传导入。
- 天数/份数策略自动清理，但至少保留最近两份成功备份；固定及正在演练/维护单引用的备份不删。明确删除只操作本模块已知UUID目录中的三种文件，遇未知文件拒绝递归删除。已删记录和审计保留。

## 恢复演练

创建随机 `media_tool_restore_<12hex>` 临时数据库，恢复、核对完整表摘要、读取所有密文并执行换钥dry-run/迁移幂等校验。没有Worker连接克隆库。正常结束仅删除该次创建的克隆库。需要DB角色具有CREATEDB；权限不足明确失败。

中断不会自动重放。演练创建数据库后保存创建证明；只有存在该证明、任务不在运行且数据库属于当前角色时，才能从维护中心清理遗留临时库。没有创建证明的未知数据库不自动删除。

## 正式恢复及回滚的权限边界

Web不是宿主机root命令代理。流程为：

1. 选成功备份或登记版本，生成10分钟有效预览。
2. 管理员输入精确确认短语、审批。页面明确显示“等待宿主执行”，审批不等于已执行。
3. 主机所有者在部署根运行维护单指定命令：

```sh
python3 scripts/ops-owner.py --root /root/docker/mediatool execute <维护单UUID>
```

4. 执行器加主机更新锁，重新验证已批准/未过期/当前版本、保护摘要、不可变Docker Hub镜像及AMD64/schema；先创建新备份，再暂停业务并等待在执行任务自然结束。无法排空则阻止，不抢租约、不强制重复业务。
5. 回滚只更换app的固定SHA镜像，不重建PG/Redis或外部容器。正式恢复停止app，在隔离库重建并校验后，事务交换数据库名，保留原库 `media_tool_before_<12hex>`，不向在线原库覆盖SQL、不删除业务卷。STRM仅补回摘要匹配的缺失原文，绝不覆盖现存不同文件。
6. 恢复后撤销旧管理员/媒体会话，账号、密码、115授权、媒体身份和播放Key保护摘要必须保持一致。旧待执行任务全部暂停；旧通知投递不自动重发；其他旧审批作废。当前维护记录、备份索引和运行采样保留，不退回旧快照。用户重新登录，完成业务核对后输入“解除维护并恢复业务”。恢复/回滚完成并不自动解除业务维护窗口。
7. 结果不明确保存主机私有phase收据，不自动重跑或静默倒退；原库、前置备份和Compose副本保留。

受控恢复要求备份最近24小时演练成功、schema相同，且当前管理员/115授权/媒体归属等保护数据与备份一致。变化即拒绝，不能用旧备份复活已撤销凭据或覆盖新媒体。跨schema自动回滚/降级明确不支持；数据库不可读或凭据/媒体已经变化的灾难恢复需所有者离线人工处理，不以“安全检查失败”冒充恢复成功。

宿主机恢复工具需要Linux AMD64、Docker、Python3及仅回环绑定的PostgreSQL端口。复制当前已核验镜像的固定ops-control二进制，调用既有postgres容器客户端；不新增容器、代理或第二套Compose。程序主密钥独立保留，不写入Web执行参数。

## 版本登记

```sh
python3 scripts/ops-owner.py --root /root/docker/mediatool register dingding229/mediatool:sha-<完整SHA>
```

只接受Hub固定SHA、linux/amd64、revision标签一致、有schema标签和Hub digest的镜像。登记由所有者CLI完成，不允许Web伪造镜像元数据。缺少schema的旧镜像显示不可自动使用，不猜测兼容性。当前发布镜像标注schema50并嵌入source revision。

## 采样、趋势与告警

每分钟Cron采样，PG按1–90天保留，按时间范围最多500桶查询。显示主机内存使用率、剩余空间、load1/每CPU负载、应用堆内存、待处理任务、最近十分钟成功/失败与执行耗时（已记录started_at的最后一次执行）。旧任务没有开始时间则未知，不推算为0；十分钟窗口计数不可相加当总量。

图表使用真实时间轴，缺失采样断线，不虚构历史；同时提供原始格式化数据。主机指标来自只读HOST_PROC_DIR，磁盘为STRM所在文件系统，不是所有挂载的总空间；应用堆内存不包含外部进程或整台主机。

内存、磁盘、每CPU负载、Worker离线和持续失败支持阈值、连续命中、冷却、确认及恢复事件。触发/重复/恢复在事务中与Outbox同时持久化；未知值不误报正常，确认停止重复提醒。发送沿用现有通知连接与投递重试，不添加新外部账号。维护暂停期间业务派发及通知投递暂缓，事件保留。

## 验收边界

隔离数据库执行真实dump/restore/临时库清理、审批与单次领取、跨schema拒绝、路径/摘要/手工输出保护；主机执行器验证固定镜像、原库保留与禁止未知结果重放。正式服务器只新建备份/克隆演练、查看页面和指标，不用真实账号/媒体做恢复或回滚试验。全套发布收据保留在私有诊断目录。
