# 内置媒体库字幕管理（H3a / schema 82）

电影、单集详情中的“字幕”区块按物理 `asset_id` 管理，版本之间不共享登记或 URL。不是绑定任意网盘文件的入口。

| 来源 | 显示与编辑 | 下载与删除 |
|---|---|---|
| 自动识别 | 沿用同目录、同视频名前缀与边界规则；可改语言/标题/默认/强制，可隐藏或恢复 | 仍由实际播放器 UA 获取115官方链接并零正文302；不能删除云盘文件 |
| 内嵌 | 从现有探测快照显示；仅覆盖显示属性，不重写快照或视频 | 保持 Embed，由播放器读取原视频；不提取、不隐藏、不删除 |
| 已上传 | 管理员自己的 srt/ass/ssa/vtt，原文件及UTF-8转换后都≤5MiB | 唯一允许 app 直接200返回的字幕小文本；删除仅登记和上传副本 |

## 存储、编码与一致性

- 默认 `/data/native-media/subtitles/<asset_uuid>/<upload_uuid>.<ext>`，由既有 `NATIVE_STILLS_ROOT` 的父目录派生独立 `subtitles` 目录；不新增环境变量、VOLUME 或 Compose 服务。官方 `/data` 持久卷覆盖它。自定义仍图路径时，其父目录也必须处于持久卷内。
- 不写媒体或 STRM 目录、不向115上传、不运行外部转码。字幕正文不写数据库或审计；登记只存相对路径、摘要、大小和属性。路径使用固定UUID身份、受限根目录、独占原子写入，读时复核普通文件/长度/SHA256。
- Unicode BOM、UTF-8、带ASCII字幕时间戳的无BOM UTF-16/32可检测。非Unicode旧编码本质可能有歧义：默认 GB18030，cht/zh-tw 文件名推断 Big5，jpn/ja 推断 Shift-JIS，eng/en 推断 Windows-1252；有乱码时删除副本后指定原编码重新上传。界面显示本次采用的编码，不声称准确识别所有文本。
- 拒绝空文件、错误扩展名、非法UTF-8/转码替换字符、异常控制字符及不符合对应字幕基本结构的内容。不会把任意二进制当媒体流通道。
- 客户端每次逻辑上传生成一个稳定 `uploadId`；相同身份/摘要重试返回原登记，不覆盖文件；丢失提交响应时保留副本以便精确核对，不擅自重复上传或删除可能已提交的文件。
- 编辑用 `revision` 防并发覆盖。删除先持久化不可播放的 tombstone，再删除自己的副本与登记；磁盘清理失败时显示“重试清理”，绝不调用网盘删除接口。
- 内嵌索引保留探测原索引（≤65535）；自动/上传外部索引从65536起持久化分配，不复用。新增、隐藏、删除或排序变化不会让旧 URL 指向其他字幕。自动字幕云盘身份与资产归属仍复核。

## 认证和协议

管理端API在 `/api/v1/media/assets/{id}/subtitles`，需要管理员会话；上传/编辑/删除还需现有同源CSRF校验。下载包装 URL 不暴露存储路径、网盘凭据或全局 STRM key。

原生 `PlaybackInfo/MediaSources` 外挂字幕保持 `IsExternal=true`、`DeliveryMethod=External`，提供 Language/DisplayTitle/IsDefault/IsForced 和 F2 认证 DeliveryUrl。媒体用户令牌、条目/库/物理版本可播放权限、UA准入均保留；提供者I/O后复核权限和隐藏状态。GET/HEAD 原生字幕路线对自动字幕仍302，对上传字幕200（HEAD无正文），内嵌提取与格式转换仍拒绝。上传响应设置 UTF-8 的 `application/x-subrip` / `text/x-ssa` / `text/vtt`、`no-store`、`nosniff`、CSP `default-src 'none'; sandbox`。视频路线不接受字幕文本结果，始终严格原始源零正文302。

## 备份与回退

数据库登记与 `/data/native-media/subtitles` 必须一起纳入持久数据备份。schema82 Up 新增登记表和索引序列，不改其他凭据；Down 仅移除新表/序列，不删除磁盘副本。Up→Down→Up只在隔离测试库验证迁移可逆，不是生产无损回退承诺。生产回退保留现有数据卷，按升级前验证备份恢复登记，绝不删除媒体/STRM文件。
