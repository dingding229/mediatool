# 管理员注册与账号密码登录

更新：2026-10-09，0.7.0-dev，数据库迁移15。

## 首次设置

1. 启动应用，确保PostgreSQL可用且数据库迁移完成。
2. 在可信网络打开管理界面。当前Docker验证入口是`http://localhost:18080`，只绑定本机回环。
3. 页面检测到没有管理员时显示“注册管理员账号”。自行填写账号、密码、确认密码。
4. 注册成功后自动进入工作台；系统关闭公开注册，不允许创建第二个管理员。
5. 之后页面显示普通账号密码登录，不再填写环境变量启动Key。

账号为3–32位英文字母/数字/下划线/短横线/点，以字母或数字开头，不区分大小写。密码为6–20个字符，支持中文和空格；不会去除密码首尾空格，不强制特定符号组合。允许粘贴、密码管理器与显示/隐藏密码。

**不生成默认账号或默认密码，也不会由开发测试替你注册实际管理员。首次注册前不要把未初始化管理端公开到互联网，避免其他人抢先成为第一位管理员。** 公网访问应在初始化后通过HTTPS进行。

## 账号与会话安全

- 密码采用Argon2id、随机独立盐、19MiB内存/2轮/1并行度；只保存PHC密码哈希，不保存明文或可逆加密密码。
- 注册与首个会话在同一数据库事务提交；单例约束与事务锁保证并发注册只有一个成功。
- Cookie使用HttpOnly/SameSite，生产环境Secure；服务端保存会话摘要、管理员ID和凭据修订。
- 登录尝试使用PostgreSQL持久化限流，重启不清空；密码计算全局并发最多2，拒绝无限排队和任意哈希参数。
- 未知账号与错误密码均返回“账号或密码不正确”。响应、日志与审计不记录密码或原始会话Token。
- `ADMIN_API_KEY`已停止用于登录和管理API，Bearer/旧Key不能绕过密码认证。
- `SESSION_SECRET_KEY`仅用于服务端签署会话，不能当登录密码；可独立生成32字节hex。没有配置时从APP_SECRET_KEY按用途派生，不复用STRM播放Key。不得随意修改APP_SECRET_KEY；它还用于业务凭据加密。

迁移15会撤销原启动Key体系的旧会话；已有服务连接、下载、媒体、播放凭据和主密钥保持不变。没有自动将旧Key转换为管理员密码。

## 修改密码

“系统设置 → 管理员账号”填写当前密码、新密码、确认新密码。成功后撤销全部已登录会话，包括当前会话，使用新密码重新登录。账号身份与文件级播放Key不会因管理员密码修改而改变。

## 忘记密码：本地离线恢复

不提供无需验证身份的公开重置接口。拥有部署主机控制权的操作者可重置现有管理员密码；不会重新开放注册或创建第二个管理员。

1. 备份数据库，停应用与全部Worker，保留PostgreSQL。
2. 将新密码写入本地0600普通文件，最多20个字符；不要把密码放在命令参数、日志或聊天。
3. 在已加载DATABASE_URL的环境运行：

```bash
bash scripts/load-env.sh go run ./cmd/admin-reset \
  --username '<已注册账号>' \
  --password-file '/private/path/new-password.txt' \
  --offline-confirmed
```

容器中工具位于`/app/admin-reset`，可按已有Compose数据库网络运行；新密码文件只读挂载，使用能读取0600文件的正确UID/GID。成功后启动原部署组合。结果未知时先核对，不盲目重复操作。工具不打印密码，也不重置业务数据。

## 自动验收与API调用

管理API使用登录后Cookie，不再支持旧管理员Bearer Key。先POST`/api/v1/auth/login`传username/password，在内存中使用响应Cookie；不要持久化浏览器明文密码。

播放验收脚本：

```bash
python3 scripts/verify-m0.py --username '<管理员账号>' \
  --base-url http://localhost:18080 --gateway-url http://localhost:18091 \
  --asset-id '<已有资产UUID>'
```

交互提示密码且不回显，也支持`--password-file`私密文件，不支持密码明文参数。脚本只向管理服务发送账号密码，Cookie不会带到CDN；结束尝试退出会话。

测试使用`bash scripts/test-e2e.sh`，仅操作隔离`media_tool_test`并在18084运行临时测试服务。测试账号随机生成，业务库不会预注册测试管理员。不要同时执行会TRUNCATE同一测试数据库的Go集成测试。

## 密码长度调整（2026-10-09）

按用户要求，新注册、修改密码和离线重置统一改为**6–20个字符，包含边界**。中文按字符计数，不按UTF-8字节计数；密码不自动去除首尾空格。已有超过20个字符的密码仍可登录并作为当前密码验证，避免政策变更锁定已有账号；下一次设置新密码时执行6–20要求。Argon2id、随机盐、登录限流和会话撤销策略保持不变。

后端新增5/6/20/21字符及中文边界、历史长密码验证；前端共享长度校验及测试，注册/修改界面提示同步。全量Go race/Go vet、4项前端单元测试、11项Chrome E2E及2项Python测试通过，Docker验证实例已更新。

## 2026-10-11：一次性密码找回

新增 `/api/v1/auth/recovery-code`（管理员会话、CSRF、当前密码复核、限流）生成 256-bit 随机恢复码，数据库只存 SHA-256 摘要，30 天有效。新码替换旧码、仅单次显示，不存浏览器持久存储。
登录页 `/api/v1/auth/recover` 需账号、有效恢复码及符合 6–20 字符策略的新密码；失败不区分不存在账号、错误、已用或过期恢复码。事务原子消耗、更新凭据版本并撤销全部会话；并发仅一个成功。常规改密和离线重置会作废恢复码。
不具备已保存有效恢复码时仍需服务器所有者进行离线恢复。不默认创建邮件服务器、不启用用户名直接重置、不把 STRM / 115 / APP 密钥作为找回凭据。

## 2026-10-12：取消后台找回，采用所有者空文件恢复

之前的恢复码界面与API已删除，旧码在迁移时清除。部署所有者创建空 `password` 文件再重启，启动控制台输出一个20字符随机临时密码，30分钟有效、登录强制换新密码，原会话全部失效。程序文件日志、后台数据浏览及文件操作看不到或创建该恢复文件。详细流程/异常恢复与私密控制台日志注意事项见 WORKBENCH_SECURITY.md。

旧离线admin-reset仍为运维工具，不是后台找回接口；普通更换密码流程保持6–20字符策略与会话撤销。
