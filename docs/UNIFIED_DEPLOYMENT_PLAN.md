# 单容器程序、镜像发布、日志及账号恢复更新计划

日期：2026-10-11。目标仓库：dingding229/mediatool。

## 约束与验收

- 官方部署只使用根目录 docker-compose.yml：app、postgres、redis 三个服务。
- HTTP 管理端、Emby 302、三个队列消费者、调度和变更监听在一个 Go 进程内运行；迁移由主程序启动时执行，不另起迁移容器。
- 既有 Emby / CloudDrive2 是外部依赖，保留已配置服务和数据，不作为本程序 Compose 服务；不能为达成数量要求删除它们。
- GitHub Actions 先运行后端 race / PostgreSQL 集成测试、前端测试及构建，再构建 linux/amd64 并发布 Docker Hub；服务器只 pull 已发布镜像。
- 日志采用内置 Go slog JSON，支持 debug/info/warn/error；Docker json-file 限额轮转，不增加 Vector / Filebeat 容器。敏感字段脱敏，不记录请求体或播放签名。
- 管理员可在设置中验证当前密码后生成一次性恢复码，数据库仅存 SHA-256 摘要，30 天过期；登录页使用账号、恢复码及 6–20 位新密码恢复，原子消耗并撤销全部旧会话。不开放账号名直接重置。已有账号不自动修改密码，未保存恢复码仍可使用原有离线管理员恢复工具。
- 保留账号、主密钥、115 授权、STRM 原文和可回滚数据库备份。继续禁止媒体中转、转码和 HLS 回退。

## 执行顺序

1. 记录本地/服务器资源清单和 GitHub/Docker Hub 发布条件，准备更新前备份。
2. 改造统一运行生命周期与内置迁移、结构化日志；添加恢复码数据库迁移、API、Vue 界面和失败/并发/撤销测试。
3. 合并 Compose，更新初始化、测试、更新脚本和文档；移除旧 Compose 文件，保留历史记录但不继续使用。
4. 排除 env、数据、构建目录和私钥，初始化 Git 并推送源码及 Actions。配置专用 Docker Hub 写入令牌（非删除权限）及仓库变量。
5. 串行跑后端 race/集成/E2E，前端单元测试、构建和移动/桌面视觉检查。
6. 等 Actions 镜像发布成功，按不可变 sha 标签或摘要从 Docker Hub 拉取；备份并迁移服务器为三个程序容器。核验持久化数据、三队列、日志和原 STRM 的 302 直链。
7. 依据路径/标签清单删除本程序本地缓存、临时二进制、镜像归档和服务器旧构建残留；不全局 prune，不删业务卷。保存精简验证报告及最近回滚备份。

## 发布依赖

仓库为空且拥有管理员权限；2026-10-11 初始核验时 Actions 没有 Docker Hub 凭据。需要变量 DOCKERHUB_USERNAME、DOCKERHUB_REPOSITORY（完整 namespace/name），密钥 DOCKERHUB_TOKEN。用户已授权通过登录的 Chrome 配置 Docker Hub。创建永久访问令牌需在最终提交前确认权限/有效期；令牌不回显、不提交源码。
