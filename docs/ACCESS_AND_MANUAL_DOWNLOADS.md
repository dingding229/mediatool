# 域名、独立媒体端口与手动下载

## 访问与域名

系统设置 → 访问与域名：

| 字段 | 反代上游（默认容器端口） | 作用 |
|---|---|---|
| 后台访问域名 | app:8080 | 管理员入口与明确允许的后台同源请求 |
| STRM播放域名 | app:8080 | 新建固定解析链接；只302至115，不中转媒体 |
| 内置媒体入口域名 | app:8092 | 独立媒体账号，根路径 `/` |
| Emby网关域名 | app:8091 | 原有Emby客户端反代入口 |

用户填写完整 origin，例如 `https://media.example.com`，不含路径/账号/查询，域名使用小写/Punycode。生产环境使用HTTPS。可为管理与STRM配置同一域名，但内置媒体域名必须反代到独立端口。后台不会自动操作DNS、证书、防火墙或反代。未设置时继续使用私有Compose中的直接配置值。部署地址仍允许登录，避免误配置导致自锁；任意Host或Forwarded-Host不会变成可信登录来源。

同一容器内运行三个HTTP监听器，不新增常驻容器或第二份Compose。`MEMBER_ADDR` 控制监听地址（默认127.0.0.1:8092，Docker配置0.0.0.0:8092），`MEMBER_PUBLIC_URL` 为未配置域名时的回退入口。修改监听地址和端口映射后重启app。独立媒体端口只提供媒体用户API与静态页面，拒绝管理员API及Emby网关。`/watch` 不再作为入口。

内置媒体库的现有能力仍是独立用户、授权目录预览与已预留的Provider；完整自研解码/播放内核尚未开放。本次端口隔离不伪称该内核已实现，Emby播放不受影响。

### 已有STRM

域名变更立即用于新生成链接与业务入库，**不偷偷改写原有STRM**。使用STRM工具先预览、确认全局修复；归属、内容摘要和播放凭据仍必须通过。旧地址不要在修复和客户端确认之前停止服务。

## 系统设置分组

访问与域名、命名与刮削、搜索与订阅、网络代理、TMDB、管理员账号、移动端应用各自有清晰保存范围，URL用 `?tab=...` 深链接；分组切换保留未保存草稿。TMDB设置负责凭据编辑与保存时验证，状态不在设置页面重复，统一在服务连接查看。

## 手动下载

下载与传输 → 手动种子下载 → 添加种子：

- `.torrent` 文件：最多10MiB，服务器解析文件清单及info hash后加密保存源内容。
- HTTP(S)种子链接：必须返回torrent原文，不是详情页；最多3次跳转、15秒、10MiB。拒绝本机、私网、元数据地址、DNS重绑定与不安全跳转。不会附带站点Cookie；需要登录的站点资源使用站点搜索下载，或提供有效的带签名种子URL。
- magnet：接受有效v1 BTIH十六进制/Base32与v2 BTMH SHA256，保持原始链接，交给已配置qB获取元数据。

任务使用下载器已保存的下载目录和分类；独立队列记录提交意图，按下载器/hash去重。提交结果未知只做刷新核对，不盲目再加种。真实进度来自qB，未知不显示伪造的0%。独立列表显示最近200项，支持原始来源、hash、目录、分类与消息回显。

**手动任务仅下载，不虚构TMDB身份，不自动上传115、生成STRM、清理本地文件或删除种子。** 需要入库时进入文件管理确认媒体身份并整理，PT H&R/做种约束由用户承担。原有搜索/订阅下载的身份绑定与自动流水线保持不变。
