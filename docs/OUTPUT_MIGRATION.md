# 身份修正与输出迁移

日期：2026-10-10；源码迁移19，发布以output-migration-*报告为准。

## 明确操作，不自动改原媒体

默认身份修正仍保持STRM位置。改变Movies/TV类型、剧集/季集或主动重新布局时，可在云盘索引→修正身份/季集勾选“同时迁移Movies/TV输出目录（先预览）”。

1. identity-preview读取可信托管清单/当前内容，在回滚的PG事务中生成完整计划，只返回相对路径和planDigest，不写文件，不改媒体绑定，不返回STRM正文/Key。
2. 查看“生成新输出”“归档旧输出”后，明确确认。请求必须携带该planDigest；资产修订、元数据、根目录/输出或内容变化将要求重新预览。
3. 事务内同时提交新STRM/NFO/完整字幕写入意图、目标STRM索引、绑定/修订以及旧输出归档意图。新输出全部完成且实际内容仍吻合之后才归档旧输出。
4. 归档只处理当前资产、asset作用域且摘要一致的托管文件；共享tvshow.nfo不归档，手工/未知归属文件不覆盖，不自动删目录。

## 稳定播放链接与恢复

- assetId、文件Key、网盘路径/原媒体、做种源文件不变。新STRM复制旧STRM正文，不因迁移重新构造或轮换播放链接。
- 旧输出保存在输出根目录下.media-tool-retired/日志ID/原相对路径.retired，保留实际字节，不再使用可播放扩展名。并非物理删除；保留期/明确批准的人工清理已作为迁移20的独立模块实现，见ARCHIVE_CLEANUP.md；默认无自动删除。
- Linux使用renameat2(RENAME_NOREPLACE)，macOS使用RENAME_EXCL；目标碰撞原子拒绝，不覆盖并发创建的归档。其他平台明确不支持这一归档操作，不做不安全替代。
- 新写入依赖逐项验证其数据库状态和真实文件内容，数据库“applied”但文件缺失/被手工改动不能提前清理旧输出。
- 归档后、DB提交前中断：已有归档内容匹配且原位置缺失时安全重放；被手工重建的原输出或改动的归档报冲突，不删除它们。
- 输出待恢复时资产artifacts_state=pending，不允许新的身份修正吞掉旧任务；恢复列表区分写入/归档。成功后再刷新Emby。
- 不执行自动逆迁移/自动删除共享NFO，不改115授权、密码、主密钥或禁止转码/STRM原链接策略。

## 字幕清单

复制同视频stem的srt/ass/ssa/vtt/idx/sub/sup/smi/ttml侧车，保留语言/forced/default等suffix；idx必须配同stem的sub，缺配对在提交前失败。一次事务提交整个清单，100项/64MiB总量、20MiB每文件上限，拒绝最终符号链接/冲突重名。不复制其他视频侧车、不移动源文件。已有托管字幕迁移保留全部清单（包括位图数据）。

NFO仍按Emby的单集格式输出，数据库保留完整实际季集覆盖。尚未把“重复episode XML标签”或其他客户端的多root NFO格式宣称为Emby识别通过；更丰富的单集provider metadata与实际多集命名矩阵仍待验。

## 验证与边界

隔离PG/文件系统覆盖电影↔剧集、跨剧集/季迁移、播放链接不变、字幕idx/sub/sup清单、共享NFO保留、手工修改、预览证明/缺失依赖、新文件改动、rename-before-commit恢复与原子no-replace。Chrome E2E覆盖默认关闭、预览不触发应用、取消、确认携带证明与手机布局。

真实部署只更新程序，不对用户已有资产主动做迁移。实际已有媒体迁移需要用户在管理页选择明确身份并确认；不能把fixture中的身份/资源当作PT业务或真实影片迁移验收。


## 非连续合集索引（2026-10-11）

同版本Emby将E01E03当范围，新非连续合集迁移必须预览每个已声明集号的独立STRM/NFO及字幕。全部复制同一旧STRM正文/Key，不伪切片；新输出完成后归档旧链。多个旧索引可收敛，但正文/KeyRef/同suffix字幕必须一致，否则明确冲突，不能猜选。每个索引的NFO提示播放完整源文件，共享NFO保留；无新迁移或自动改用户文件。详见EMBY_EPISODE_PROJECTION.md。
