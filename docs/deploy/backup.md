# 备份、演练、恢复与回滚

[文档目录](../INDEX.md) · [运维页面](../guide/ops.md)

## 备份包含什么

“运维 → 备份与告警 → 备份管理”可创建系统备份、查看结果、下载、固定和按条件删除。

备份包含同一只读数据库快照、清单及已登记的受管 STRM/NFO/字幕。输出缺失、摘要不符、越界或被手工修改时会明确失败。**不包含应用主密钥、115 原媒体、下载器做种源，以及 Emby、CloudDrive2、下载器的外部配置和卷。** 这些内容必须独立保管。

数据库备份可能包含敏感内容，私有保存，不提交版本库或公开共享。主密钥与备份分开保管，恢复时必须匹配。固定备份及正在演练或维护单引用的备份不能自动删除；保留策略至少保留最近两份成功备份。

## 创建与下载

1. 点击“创建系统备份”，确认范围。
2. 等待排队和执行；查看“备份详情”，不能把已排队当作备份成功。
3. 备份就绪后可“下载备份”并保存在自己的私有存储。
4. 需要自动执行时，在“维护策略”配置备份计划和保留范围。

## 恢复演练

点击“恢复演练”，程序在专属临时数据库恢复并核对数据，不覆盖业务库，任务进程也不连接该临时库。演练要求数据库角色有创建数据库权限。

正常结束只清理自己创建的临时库；中断后由维护界面核对创建记录，符合条件才可“清理临时库”。不能对未知数据库做自动删除。

宿主命令也可核对备份：

```sh
./media-toolctl --root "$PWD" backup-verify
./media-toolctl --root "$PWD" --archive /私有备份目录/backup.dump backup-verify
```

这只验证备份内容和恢复可读性，不代表全部外部服务和真实媒体已经恢复。

## 网页与命令行恢复（schema 77，所有者2026-10-22确认）

**全部 public 业务数据随备份回退**：管理员/媒体账号和密码、115授权与连接凭据、设置、云盘索引、媒体条目、STRM登记、插件实例/配置/权限/KV、历史等全部替换为备份时的值；不再要求这些表与当前一致。空业务库、数据被误删或逻辑损坏也可恢复，不要求当前密文可读。

### 网页操作

1. 在“运维 → 备份与告警 → 恢复与回滚 → 网页备份恢复”选择就绪备份。列表显示来源、时间、schema、大小、SHA256及是否经过预览。
2. 预览校验完整性、当前独立master key、备份内全部密文及候选库向上迁移。高于程序schema拒绝；低版本只在独立候选库升级。表格列出每张将回退业务表的当前/原备份行数及差额；**行数相同也会回退行内容**，旧schema升级可能初始化新增表。
3. 阅读三项高风险提示：“管理员账号与密码将回到备份时状态”“115授权将回到备份时的令牌，可能需要重新授权”“当前登录会话将失效”。输入原确认短语 `恢复 <完整备份UUID>`，仍要求CSRF和10分钟内新近登录。
4. 202只表示排队。执行器暂停调度与业务写入，等待运行任务/插件和写入屏障结束（最多120秒）。**先强制创建恢复前快照，失败中止。**
5. 在单事务内替换业务表数据。失败自动回滚到本次快照；补偿也失败或提交不明则保持维护unknown，核对而不盲目重放。成功后保留快照，执行记录可再次“预览回滚到恢复前”，仍走相同流程。
6. 账号与会话在提交时原子切换，旧会话撤销。浏览器保存的只是恢复回执UUID，不是凭据；401后提示使用**备份时**的账号密码重新登录，回到运维恢复页查询保留的结果，不重复提交。其他浏览器同样需要重新登录。running/pending期间登录写入暂停；提交后中断而变unknown时，仅在PG维护客户端已退出后允许新登录核对。核对结果不会再次撤销用于核对的新会话。

### 命令行：同一个app内执行器

在私有Compose目录执行（不复制二进制到宿主机、不停app、不更换DSN/数据库名）：

```sh
docker compose exec -T app /app/media-tool ops restore-preview -id <备份UUID>
# 阅读restore.tableChanges、warnings、确认短语，复制真实预览ID和digest：
docker compose exec -T app /app/media-tool ops restore-execute \
  -id <预览UUID> -digest <预览digest> -confirm-text '恢复 <备份UUID>'
docker compose exec -T app /app/media-tool ops restore-status -id <预览UUID>
# 只核对中断记录，不重跑导入：
docker compose exec -T app /app/media-tool ops restore-reconcile -id <预览UUID>
```

`restore-execute`等待共享执行器的结果；命令中断不能作为未执行的证据，应先查status。已有“审批维护单”与 `media-toolctl execute <维护单UUID>` 仍保留，数据恢复转交同一app执行器，使用相同快照、事务导入、补偿和回执，不再走宿主停机/改名数据库分支。旧版宿主工具尝试claim/prepare/finish数据恢复会在停app前被明确拒绝；更新工具或使用上述app内命令，不能回退到旧停机换库旁路。镜像回滚仍是独立的所有者流程，需匹配schema和不可变Hub镜像。

### 事务、恢复范围与例外

- 导入只替换public业务数据：保持当前已迁移的表/索引/约束，不DROP/TRUNCATE在线账号表，不禁用触发器或外键。按外键依赖先删子表、再COPY父表；SHARE ROW EXCLUSIVE锁排除其他写入但允许普通SELECT。认证/进度通过MVCC读取提交前版本，提交后读新账号和已撤销会话。进度查询不写活动时间，其他活动记录写入有100ms上限且失败不影响认证。
- 仅下列协调/备份账本保留当前值：`ops_mode`、`ops_releases`、`ops_backups`、`ops_drills`、`ops_requests`、`ops_request_verifications`、`ops_web_restores`；另保留`goose_db_version`，`ops_restore_commit`由导入事务更新。**ops_policy、ops_samples、ops_alerts不在例外中，也随备份回退。**
- 运行态安全归一化：旧管理端/媒体会话撤销，旧pending/retry/running任务暂停，未决通知/插件运行核对后再执行，worker generation/lease失效；插件旧事件消费游标收敛到已备份日志末尾，旧磁盘状态任务标失败且不执行清理，旧wake-job绑定清除；不会因恢复重放外部副作用。插件配置、KV与业务字段仍来自备份；已安装定义按当前pin校验，扩权仍停用待确认。序列只前进，保留备份/当前计数器与已恢复行的最大值，失败可留ID空洞，不回退复用ID。
- 包含database.dump、清单、登记的受管输出；**只补当前缺失且包内摘要正确的STRM/NFO/字幕**。现存输出相同则不写、不同仍拒绝覆盖；失败后已补回的文件保留，不做删除。
- master key、Compose、环境变量、其他/data配置不随备份；不删除磁盘媒体、STRM正文、downloads、qbittorrent-downloads、logs，不接触Emby/CD2等外部卷，不下载媒体或字幕正文。
- 最近恢复前快照计入保留策略且不可被清理；固定快照继续保留。自动补偿只允许返回本次刚创建、同schema、完整库存/摘要匹配的快照，即使原库密文本来已损坏，也按原样返还；**这不豁免手动预览/恢复的密文校验**。物理损坏若导致强制快照失败，仍中止，不能绕过安全底线。
- 其他schema不参与；外键循环、缺少候选数据对象、schema与程序不匹配会明确拒绝，不擅自关闭完整性约束。生产恢复测试禁止，集成/E2E只用media_tool_test与Redis DB15。
