# 文件与入库下一阶段详细开发计划

## 1. 前置门槛与本轮边界

资源获取优化完成、测试和Docker Hub镜像部署通过后，才开始以下阶段。本轮只编写规划，不批量移动真实文件、不启动真实PT下载、不改已有STRM正文/播放Key。

沿用Go模块化、Vue3、PostgreSQL、Redis，以及唯一docker-compose.yml中的app/PostgreSQL/Redis三个服务。CloudDrive2、Emby、下载器是外部依赖。业务计划统一cron；不为整理/扫描/通知增加独立容器，也不提供视频中转或转码。

## 2. 现有基础（不是从零重写）

- `internal/modules/filemanager`：自动本地根目录、CloudDrive2后端、List/Preview/Execute、索引保护、侧车关联、操作摘要与未知结果核对；本地使用受限os.Root和不覆盖重命名。
- `internal/modules/library`：云盘扫描、候选识别、已确认媒体资产、定时/变化扫描、托管STRM/NFO、归档与修复记录。
- `internal/modules/acquisition`：下载原文件保留做种、CloudDrive2上传验证、传输任务、独立入库恢复批准、Emby刷新与逐路径可见性确认。
- `internal/modules/metadata`/系统设置：0day信息提取、电影/剧集身份、用户命名模板。
- Vue文件管理/云盘索引/STRM/整理历史页面已存在，但跨模块流程、批量操作可用性、真实目录验收与失败恢复需要集中梳理。

已有安全围栏和文件级身份应复用，不能以UI重构替换为直接改路径/覆盖文件。

## 3. 阶段划分

### F0：目录与能力盘点（首先实施）

**内容**：梳理本地/115目录树和读写能力，区分下载源、115目标、托管STRM输出、归档区；自动发现本地挂载，不新增“绑定本地目录”步骤。只读挂载明确标注；下载做种源禁止移动/删除。CloudDrive2与115授权、Emby路径映射分别展示。

**接口**：复用文件根目录/列表API，补充能力DTO（read/write/move/recycle、source/output、连接状态）。不得允许访问宿主根目录、Docker Socket、数据库卷、password恢复文件或日志私密目录。

**验收**：真实只读列目录；本地符号链接/跨根越界/下载源写入/只读目录写入测试；390px目录选择与返回上级操作可用。

### F1：云盘索引与增量对账

**内容**：完善扫描范围、分页、进度、暂停/取消、断线恢复；支持cron全量校准与文件变化合并。扫描不完整/失败不得判定媒体丢失；缺失需要多次完整覆盖证据，删除事件不直接删除资产/STRM。

**数据**：沿用cloud_files/library_scans/候选记录，明确扫描覆盖范围、游标、时间、连接版本、失败原因。按稳定文件ID/PickCode关联，不仅靠文件名。

**验收**：深层目录、空目录、重复事件、改名移动、网络中断、根目录改变、扫描同时文件变化；可继续而不重复建资产。

### F2：识别与人工纠正工作台

**内容**：0day解析标题/年份/季/集/分辨率/来源/编码；电影、单集、合集、特别篇分流。TMDB唯一明确匹配才预选；重名/年份冲突/合集覆盖未知进入待确认。允许更换身份、逐文件/批量确认，但不能把关键词当作媒体身份证明。

**接口**：识别预览返回原名、候选、置信证据、季集集合、缺失项、冲突原因；确认API绑定当前文件和候选修订号。

**验收**：中英混合、别名、无年份、跨季合集、多版本、样片、字幕；不确定项不自动重命名或入库。

### F3：模板命名与分类移动

**内容**：电影/剧集分别按设置中的模板规划名称与目标分类；支持自定义名称，默认模板；展示逐项旧路径→新路径、目录创建、关联字幕/NFO、覆盖冲突、权限和做种保护。

**数据与状态**：复用filemanager计划/步骤日志，增加批次展示和逐项状态。`preview → approved → running → applied / needs_reconciliation / failed`；预览有TTL、摘要及修订号，执行前重新核对源文件/目标占用/身份。

**安全**：只创建缺失目标目录；不覆盖同名、不移动做种原文件；字幕语言后缀保留；本地与115动作分别核对。网络结果未知先读回状态，不重复移动。

**验收**：重复提交幂等、同名冲突、权限拒绝、源文件变化、部分成功、中断恢复；先在隔离目录验收，真实媒体操作必须逐批明确确认。

### F4：STRM/NFO与媒体集合一致性

**内容**：批量生成/补齐托管STRM、NFO及字幕，展示预览和实际结果；剧集按照已证明的季集覆盖建立文件，不猜测缺集。保留原稳定strm302入口、资产ID和文件级授权。

**安全**：用户手工文件和未知所有权文件不覆盖；库内改名/分类不能导致旧授权指向新文件。变更布局需新预览与明确批准；旧输出先有可追溯归档，不能静默删除或自动迁移。

**验收**：中文/特殊字符、季集别名、多个版次、NFO字幕对应、并发输出修复、原播放Key不串文件；原STRM→302→115 CDN/Range复核，不引入25015静态流替代原URL。

### F5：下载完成接管与入库流水线

**内容**：将“下载完成”“上传完成”“云端校验完成”“STRM/NFO写入”“Emby可见”分开显示。下载路径与主程序共享目录映射须真实可读；上传使用可恢复会话，按大小/可用哈希确认云端文件；已有云端匹配文件可核对复用而非重复上传。

**数据**：复用download_files/transfer_tasks/资产绑定及输出日志，显示阶段、字节进度、重试、暂停理由和批准摘要。上传100%不代表Emby入库或播放器可解码。

**验收**：零字节/大小不符、哈希未知、重复提交、会话失效、取消后的未知结果、重启、资源改变；下载原文件持续可做种。真实PT资源全流程需单独选择合法测试样本，不能从只读搜索验收推断成功。

### F6：Emby确认与播放验证

**内容**：按明确库/目录刷新，逐路径确认STRM可见与媒体身份，显示待刷新/已可见/确认失败；不把Emby刷新HTTP成功当作媒体已入库。保留媒体库/用户权限差异。

**验收**：路径映射错误、Emby不可达、重复媒体、用户不可见、多季多集；选原生客户端和浏览器分别做302/CDN验证。容器/音轨解码兼容性单独记录，不恢复转码或中转兜底。

### F7：历史、恢复、归档清理与通知

**内容**：统一整理/上传/输出/Emby确认历史，按批次、媒体、来源、状态和时间筛选；失败可查看具体阶段并读回核对。确认后的安全归档支持保留期、预览和明确清理批准；不能清理做种源、未核对文件或未归属输出。

**通知**：沿用独立通知模块，对成功/冲突/需要确认/失败发事件；同一任务避免重复通知。日志保留debug/info/warn/error及原请求/302链接，管理后台原值展示，私密日志不进入GitHub/CI。

**验收**：历史分页与移动端详情；权限保护、恢复幂等、批准过期、实际大小/空间展示、归档恢复/清理边界、通知重试与去重。

## 4. UI顺序

1. 文件管理：左侧目录/根目录切换，右侧文件表或移动卡片，统一动作入口、当前能力/权限。
2. 云盘索引：扫描进度、待识别/待确认/已确认/异常筛选与批量识别工作台。
3. 整理预览：逐项对照、命名模板、目标树、冲突理由，确认按钮与取消明确分离。
4. STRM：资产集合、输出归属、原地址/当前解析诊断、修复/归档流程。
5. 整理历史：时间轴/批次摘要、步骤详情、恢复/重新核对入口，不能只显示“成功/失败”。

统一现有设计系统，小海报带外框，按钮44px触控与8px以上间距，真实数据/加载/空状态/失败分开显示。

## 5. 每阶段发布与完成标准

- 先写阶段计划和验收样例，再代码；保持模块和接口职责，不增加旧版数据/插件兼容分支。
- Go/PG/Redis/文件系统/gRPC隔离测试、Vue单测、桌面与移动E2E；数据库测试串行，仅media_tool_test/Redis15。
- GitHub → Actions AMD64 Docker Hub →指定服务器不可变镜像；更新前备份、保留近期回滚和实际账号/授权/媒体。
- 路径/身份/授权/同名冲突/未知结果围栏任何一项不通过，该阶段不自动执行真实媒体操作。
- 文件管理、索引、整理、输出、入库、播放、完整解码各自验收，报告实际通过和未测部分。

**建议首轮**：F0 + F1 的只读体验、能力标注、扫描进度/错误恢复。再推进F2 + F3的预览/隔离操作，最后连接F4–F7的真实全流程；不一轮同时上线未经验收的批量移动和自动清理。
