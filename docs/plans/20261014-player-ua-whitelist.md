# 播放器 UA 访问记录与白名单

2026-10-14。目标：管理员可查看播放入口实际收到的 UA，并从记录加入白名单，显式启用后拒绝未匹配播放器。不替换既有身份/文件授权，不修改 STRM 或实际115取链 UA。

## 策略

- 全局播放 UA 策略，默认关闭限制但记录访问。统一覆盖固定 STRM GET/HEAD、Emby PlaybackInfo/视频/音频/下载入口、预留 member playback。后台、Emby登录/浏览/海报/字幕不受影响。
- 白名单支持区分大小写的完整匹配（默认）和显式前缀匹配。不使用模糊包含、任意正则或自动信任记录；空 UA 在启用后拒绝。
- 来自记录的添加使用原始完整 UA 并保存备注；管理员也可手动添加/编辑/删除。显式启用需至少一条有效规则；启用、修改、删除均有乐观revision与审计。
- UA校验必须发生在缓存直链返回、云盘解析和Emby上游请求之前；命中只代表“通过UA检查”，不代表登录/文件授权/播放成功。未匹配403，策略不可读取503，不返回CDN Location。
- PG存储策略与规则，不使用有窗口期的Redis策略缓存；修改对随后请求立即生效。开发无DB的纯单元测试保留显式不限流环境，正常部署数据库失效不放行。
- UA记录按完整UA摘要聚合：原值、首次/最近时间、请求/通过/拒绝计数、入口、方法、实际连接IP、匹配规则及策略修订。最多2000种UA，淘汰最旧记录；max UA4096字节、单页<=100，支持搜索/是否白名单筛选和清理。常规日志保留完整请求与302目标；聚合表不重复存永久播放密钥。
- 重复/含控制字符/无效UTF8/超长 UA 返回400；不截断成可加入白名单的值。
- UA是客户端声明，可伪装；它是播放器使用策略而非强身份或DRM。已发出的115 CDN链接无法由本程序的UA规则追溯撤销，须依赖原令牌有效期。

## 实施顺序

1. migration45 + `playeraccess`领域模块、请求入口识别、策略决策/聚合记录与管理API。
2. 在HTTP入口统一拦截，与未来member接口共用；每次保留原UA，不使用白名单值替换115解析UA。
3. 独立“播放器访问”页面：当前启用状态、规则表、访问记录、完整UA详情、从记录添加、清理；响应式布局和明确确认。
4. 匹配/大小写/空UA/路径变体、HEAD/PlaybackInfo、无权限/缓存不绕过、原UA传递、记录及数据容量、CSRF/角色权限、并发修订测试。串行Go竞态、Vue构建、Python及浏览器测试。
5. GitHub → Actions AMD64 → Docker Hub不可变镜像 → 服务器仅更新app。保持限制关闭，生产不创建测试白名单或改变账号；只读验证真实UA记录、原STRM302/CDN206及数据保留。清理临时构建与SSH文件。
