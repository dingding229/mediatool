# 内置媒体库与独立用户系统

日期：2026-10-14。范围：可运行的扩展骨架与媒体用户系统，不在本轮替换 Emby。

## 技术决策

- 首选 Go 内置媒体服务，复用 PostgreSQL、Redis、115 解析及现有资产模型；Vue/TypeScript 负责用户端和管理 UI。不新增容器、Node 服务或第二份 Compose。
- `mediaserver.Provider` 定义版本化能力描述、媒体库列表、分页目录、播放授权入口；已有 Emby 以适配器保留。未来 TypeScript 实现须遵守同一 v1 JSON 契约，通过受控适配器接入，而非加载远程脚本。
- 不切换默认提供者，不改既有 Emby HTTP/播放器协议。内置媒体库先提供已确认、文件在库的电影/剧集只读目录；播放票据、播放进度、多客户端协议等明确为 reserved。

## 本轮实施

1. 新增 Provider 契约、注册表、Emby 目录适配器、内置目录提供者。管理员原有目录查询通过适配器接入，结果与现有接口保持一致。
2. 独立媒体用户表、会话表、权限表与登录限流表。管理员创建/编辑/禁用/删除媒体用户、重置密码、撤销全部会话；默认无媒体库权限，首次登录和重置后强制改密码。密码 6–20 字符，Argon2id，不回显哈希。
3. 媒体用户使用独立 cookie/会话，不共用管理员注册或后台权限；无公开注册。变更权限、禁用或重置密码立即撤销旧会话。读写均校验当前数据库状态，故障关闭；限制密码计算并发、登录频率及请求体。
4. 初始逻辑媒体库为 movies / series，仅按已确认媒体类型划分；显式授予浏览/未来播放权限。未确认、缺失、已回收文件不暴露。媒体 DTO 不含云盘路径、115 pickCode、STRM/global/file grant、上游账号或配置。
5. 新增“自研媒体库”和“媒体用户”后台页面，以及 `/watch` 独立媒体登录/目录入口。目录海报走媒体用户授权图片入口。未实现的播放接口返回 501，不偷偷使用管理员 STRM 密钥或回源。
6. 补充跨用户/跨身份会话隔离、强制改密码、权限撤销、CSRF、限流、目录过滤、接口契约、响应式 UI 测试与 API 文档。
7. 全套串行验证后提交 GitHub，等 AMD64 Docker Hub 镜像发布，使用不可变镜像仅更新服务器 app；只读验收并核对原有账号/授权/STRM/容器，不创建生产示例用户。清理本任务构建残留。

## 接口边界

- 管理端 `/api/v1/media-server/providers`、`/libraries`、`/users`、`/users/{id}`、`/users/{id}/password`、`/users/{id}/sessions/revoke`。
- 用户端 `member 专用登录、会话、改密、退出 API`、`/libraries`、`/libraries/{id}/items`、`/libraries/{id}/items/{item}/poster`、`/libraries/{id}/items/{item}/playback`。
- Provider 仅报告自身实际能力；member 端仅 builtin，Emby 的管理 API Key 不转授用户。
- 未来票据必须绑定用户、资源、设备/UA、短 TTL 与授权版本，支持撤销；服务端以实际播放 UA 解析115临时 URL 后302到 CDN，禁止媒体流量代理/转码。未实现前不签发票据。
