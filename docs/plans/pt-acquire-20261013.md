# PT适配与资源获取工作台计划（2026-10-13）

## 第一阶段：实际站点证据与核心修复

1. 私有只读采集当前SSD/CHDBITS/TTG/UBITS及正常系数样本的搜索/账号/做种页面，定位实际DOM、分页查询差异和优惠标记。不提交Cookie/UID/Passkey/下载地址或完整生产页面，不绕过挑战。
2. 修复SSD副标题；CHDBITS/UBITS分页只接受当前同源、同路径、同搜索条件的实际页码变更。仅允许模板声明的等价默认查询值，不能把任意换查询链接视为下一页。
3. 优惠标记覆盖正常/免费/折扣/未知。明确正常证据才能填写1，未知标记仍保留未知，不猜零或免费。SSD/TTG/UBITS做种列表/汇总按实际页面适配，完整性与未知/零区分不取消。
4. 模板仓库多行Go定义和版本更新，冻结脱离真实凭据的DOM回归样本，主程序固定新模块版本构建。

## 第二阶段：筛选、缓存和媒体信息

5. 分辨率/来源/编码/站点多选：同类OR、不同类AND，后端完整快照筛选/排序/分页；兼容单个旧参数，不改变下载资源身份。
6. 模板网格/列表切换，保存显示偏好，保留图标/版本/网址/全选与加载状态。
7. 独立“TMDB缓存”和“搜索缓存”页面，管理员分页查看内容、TTL/大小/计数，清除单项或该类缓存需确认。严格限定Redis命名空间，搜索历史和缓存区分，不删除数据库搜索记录或其他缓存。
8. 搜索顶部媒体卡片：已确认TMDB身份、海报/背景、名称/年份/类型/分类/简介，详情与创建停用订阅入口。站点直搜不擅自认定相似媒体，先选TMDB候选；详情复用TMDB配置，失败有状态，UI不暴露Token。

## 第三阶段：UI与发布

9. 统一资源获取模块（搜索/订阅/PT站点/模板/下载与传输/两个缓存页）的标题、筛选、状态、空/加载/错误展示和移动端布局；以既有视觉体系为基础，不破坏现有功能。
10. 串行Go/PG/race/vet、Vue/构建/Python、E2E/截图，实际站点只读验收。先推模板→固定依赖→主程序GitHub Actions AMD64→DockerHub不可变镜像→服务器备份更新。

保护：仅app/PostgreSQL/Redis；账号/授权/master key/媒体/原STRM/外部Emby/CD2不删除不替换。保持严格STRM→302→115CDN，不增加媒体中转。未知/分页部分结果必须继续如实显示。
