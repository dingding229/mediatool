# 2026-10-14 资源获取优化与后续入库规划

## 范围与顺序
本轮先完成资源获取模块，验证/发布后提供文件与入库的详细下一阶段计划；不在本轮对真实媒体做重命名、移动、下载或清理业务数据。

1. **独立结果页**：新增持久搜索运行路由；TMDB标题/站点直搜提交后及全部“查看结果”入口进入独立结果页。原搜索页面只负责输入、媒体选择和最近记录。结果页保持筛选、排序、站点状态、媒体确认下载和历史结果刷新恢复。
2. **界面**：小海报媒体卡片加单层外框；缓存不显示有效期设置/大小，操作统一按钮；TMDB剩余时间按小时，站点结果区分运行中、可复用剩余时长、到期历史。删除资源搜索顶部站点管理入口；PT右侧操作按钮统一宽度、间距和移动布局。
3. **站点正确性**：用认证/空结果明确证据识别HDSKY“余红旧事”零结果，不把解析损坏、挑战或未登录视为成功空列表。修复五站RSS自动获取；用户ID/RSS提供自动结果与手动覆盖，明确回显、保存并自动验证。
4. **代理**：增加独立网络设置，支持TMDB与PT搜索/相关获取分别启用代理；验证协议/地址，采用显式传输，不影响115直链、Emby、CloudDrive2或下载器。代理凭证加密，不把生产代理/站点内容提交仓库。
5. **订阅**：移除“明确允许H&R未知”开关，新增“拒绝下载H&R”规则并在评估和实际下载复核；未知H&R保持安全拒绝，规则结果说明原因。增加历史订阅查看，保留评估及下载关联，避免物理删除历史。
6. **测试与发布**：Go/Vue/Python/E2E覆盖（DB测试串行且仅隔离数据库），桌面/移动截图、真实只读站点/RSS验收。主程序/模板仓库如有改动均推送；Actions AMD64 Docker Hub发布后通过镜像更新服务器，复核原STRM 302与授权/媒体保持。
7. **入库下一阶段**：基于实际代码缺口编写详细的文件/云盘索引/识别/整理/STRM/Emby确认/恢复/审计开发计划，注明接口、数据、阶段、验收与失败边界。
8. **清理**：仅删除任务/程序的构建输出、临时诊断二进制、临时SSH材料；保留业务数据、凭证和近期回滚备份。

## 验收原则
- 搜索结果独立路由可直接刷新，不能依赖仅存在浏览器内存的媒体上下文。
- 真实空搜索与失败严格区分；RSS来源/用户ID变更有同源及账号验证，不盲目拼接站点URL。
- 代理只作用于管理员明确选定的模块，明确显示失败而非静默绕过代理。
- 本轮不触发真实PT下载/订阅自动下载或媒体移动；API/规则操作用隔离测试。
- 部署完成与完整真实下载—上传—入库业务验收分别报告，不混为一谈。

## 当前实现与证据
- 原HDSKY空响应的明确标记单独识别；现在实站资源会随上传变化，不将历史零结果当作永久没有资源。
- RSS实站已取得：HDSKY/OURBITS/CHDBITS/SSD/TTG/UBITS。OURBITS按实际JS表单序列化契约；UBITS保留动态CSRF；TTG采用rsstools.php生成putrss.php；CHDBITS优先带passkey的下载链接，避免错误链接触发限频。
- 历史订阅采用归档而非物理删除，评估/决策/下载关联保留。
- 代理凭证独立加密并加入主密钥轮换范围；不启用服务器未提供的代理地址。
- 文件与入库下一阶段计划见 `20261014-files-and-library-roadmap.md`。
