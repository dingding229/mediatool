# 系统设置、域名与手动下载实施计划 · 2026-10-15

## 目标与边界

1. 系统设置拆为可深链接的「访问与域名 / 命名与刮削 / 搜索与订阅 / 网络代理 / TMDB / 管理员 / 移动端」页签；统一标题、说明、表单、保存反馈与移动端布局。只保留一处 TMDB 配置编辑，连接状态集中到服务连接。
2. 后台提供管理域名、STRM播放域名、媒体用户域名、Emby网关域名设置。保存完整 HTTP(S) origin，不接收路径、用户信息、查询与片段；显式配置只允许域名（非IP），未设置时保留部署回退地址。保存立即影响链接和可信源校验，不接收任意 Host/X-Forwarded-Host。已有STRM不静默改写，沿用STRM全局修复预览与授权流程。
3. 同一 app 内新增独立媒体用户监听端口，根路径 `/` 为入口，不使用 `/watch`。只暴露媒体用户 API/海报/公共静态文件，拒绝管理 API、管理员登录及Emby。管理端不再托管媒体用户页面；账号与媒体权限不变。监听端口在唯一 Compose 直接配置，域名反代映射到对应端口，不增加容器。现有内置媒体库仍为已完成的目录预览与用户能力，不伪称已实现完整自研播放内核。
4. 种子文件与HTTP(S)种子链接、magnet 手动下载：复用 qB 凭据与下载根目录、持久化队列、种子校验、真实进度。独立手动下载任务不伪造TMDB身份、不自动上传/删本地/入库。支持明确结果待核对，不盲目重复提交；已存在hash去重。文件与链接请求有大小/时间限制、权限检查。HTTP种子链接使用防SSRF受限取回，不接受本机/内网、私有跳转或超大内容；magnet校验hash再交给已配置下载器。
5. 测试覆盖域名校验、动态链接、同源/CSRF、独立监听隔离、种子/链接/磁力校验、任务去重、错误与真实进度，Vue及E2E检查设置页全部分类桌面/移动布局。
6. 先完成本地和Actions验证，AMD64发布Docker Hub后更新服务器app；仅在私有Compose补充独立媒体端口，保留其他直填参数与PG/Redis/外部依赖。没有用户提供的域名不猜测、不更改DNS/公网证书；上线验证使用既有访问地址并确认配置入口可用。

## 视觉约束

沿用 Field Notes：浅灰底 `#f5f6f8`、白面板、深色文字 `#202c38`、次级文字 `#626d7b`、绿色操作 `#146e63` 和既有系统字体。左对齐、统一最大内容宽度、分组页签而非一屏堆叠多套表单。每个设置块明确其保存范围；切换页签保留未提交内容，不隐式保存。移动端页签在容器内滚动、表单单列、触控44px、不隐藏长值。
