# 目录分类、上传入库与 STRM 管理更新计划

日期：2026-10-14；基线100d95e / 0.24.0-dev / migration47。

## 一、上传、命名与身份一致性（1、2、3、5、13）

- 分开显示传输字节进度、云端校验和入库进度。115秒传/少量分片传输不能继续显示总体0%，也不能伪造实际上传字节；显示阶段、传输方式、实际字节和错误。
- 使用统一布局模块：确认的TMDB身份 + 系统命名模板 + 目录分类规则，生成云端媒体路径及STRM相对路径。电影/剧集/季0/多集文件正确处理，下载做种源保持原名。准备新上传时冻结布局快照，配置变化不改写正在上传的会话。
- 新文件名不添加无意义的资产UUID/短hash。发生同名冲突时阻止覆盖、要求明确处理，不靠隐式随机后缀绕过。
- 已有云端/托管输出使用明确预览和迁移流程，不自动覆盖手工文件、不改变文件Key或原STRM正文。
- TMDB搜索到站点结果时用冻结的TMDB ID/类型和确认的标题、原名、年份及季集进行严格匹配；副标题中的同名别名不是身份凭据。提供明确的未确认/不匹配证据，不将不相关资源绑定或下载为所选媒体。站点直搜保持正常关键词搜索。

## 二、目录分类（4）

新增独立“目录分类”页面及持久化规则：分类组、有序子规则、启用/编辑/删除/调序；优先级首次匹配，组内条件AND、同字段多值OR，支持类型、题材、国家/地区、原语言。预置截图中的动漫（日/国/韩/美/其他）、电影（演唱会/纪录片/动画/华语/日韩/欧美/其他）和电视剧（纪录片/儿童/综艺/国产/日韩/欧美/其他）。规则预览展示命中依据与目标路径。未知信息只进入兜底，不猜国家。

## 三、STRM与历史界面（7、8、9、10、11、12）

- STRM目录增加电影/剧集筛选；条目显示海报、身份、实际STRM路径/状态；按钮统一为查看内容、输出管理和明确修复相关操作，原云盘路径作为独立来源信息，不混淆STRM文件名。
- 支持预览托管STRM的实际正文，校验归属/摘要，不返回伪造内容。
- 新生成/修复输出自动排队定向刷新并核对Emby；cron定期对账，未知/失败如实显示；移除人工“定向刷新并确认”按钮，不宣称刷新请求等于已入库。
- 修复入口不再要求选择条目。全局检查所有托管STRM，分页/分批持久化处理；预览摘要→明确批准→后台执行。只恢复有可信原文证明的缺失文件，手工更改、冲突和摘要不一致跳过并说明。
- 历史采用截图的信息布局：媒体海报/身份/季集/分类、来源→目标、来源/方式、时间/状态、统一操作菜单；增加关键词/来源/方式筛选，移动端卡片。

## 四、外部API与导航（6、14、15）

- 增加独立API凭据/权限管理、有效期、撤销和调用记录。默认只读，明确授权才能调用搜索、预览等操作；不复用管理员密码或STRM播放Key，不向外部API开放凭据、密码重置与原始数据库。
- 提供版本/健康、分类和命名预览、媒体/STRM查询与正文、搜索/任务状态等接口及调用文档。鉴权、权限不足、过期、限流均有回归。
- 移除所有“启用为主连接”选择；替换为正常启用/停用语义或授权就绪自动启用，后端继续确保单实例服务不会产生歧义，PT可多站点。
- 左侧各入口使用独立且语义清晰的图标；新增分类/API入口，保留默认收起与移动端交互。

## 验证与发布边界

串行隔离Go/race、Vue、Python、浏览器测试；截图检查；commit/push→Actions AMD64→Docker Hub不可变镜像→服务器只更新app。保持根Compose三服务、所有凭据/115授权/最新UA策略、原STRM/NFO和其他容器；不使用真实媒体做破坏性夹具。生产只读验收，新分类/模板不自动移动既有媒体。保留回滚并清理限定构建残留。实际完成/部署以私密验收收据为准。

## 五、上传后清理（追加需求）

- 默认关闭，系统设置可明确开启“全部媒体云端校验并入库后删除本地下载文件及qB种子”，展示做种/H&R风险并要求确认。
- 任务冻结清理意图；已有任务可明确批准清理，不因设置变化自动批量删除历史任务。
- 必须核对所有需上传媒体均已校验、源大小/hash、qB真实hash/保存目录/任务标签/文件列表，无冲突才能调用qB删除种子与对应本地文件；不调用主机递归删除、不清空整个下载目录。
- 缺少可信证据、H&R未满足或未知、共享源文件、失败上传/不完整任务不清理；结果不明只做核对，不盲目重放；保留审计/历史和恢复指引。生产不执行删除作为测试夹具。
