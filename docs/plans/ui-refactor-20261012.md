# UI 重构计划与验收范围

## 目标
基于现有功能统一工作台 UI，不更换 Vue/Element Plus，不修改 Go API、数据库
模型、播放策略、管理员恢复流程和媒体整理的安全确认。

## 实施顺序
1. 建立可复用设计令牌和功能导航模型；按媒体浏览、资源获取、文件入库、系统运维分组。
2. 重构工作台外壳、手机模态导航、键盘快速前往和页面定位。
3. 用真实服务/任务快照重构总览；移除过时的建设进度与未实测状态说明。
4. 重构 TMDB 搜索表单、结果与错误/空状态；统一媒体卡片、表格、连接表单、日志/数据库详情。
5. 验证全部原有页面/敏感字段/危险操作、强制重设密码、深链接；执行单元、构建、Go、E2E。
6. 保存实际截图；推送 GitHub，确认 Actions 发布 AMD64 Docker Hub 镜像，再使用
   不可变 sha 镜像更新指定服务器；保留私有 Compose、凭据、数据库卷和外部 Emby/CD2。
7. 验收健康状态、静态资源版本、真实页面和原 STRM → 115 CDN 302 链路。

## 新增回归
- 导航入口唯一性和搜索关键词；旧 Emby/连接深链接定位。
- 快速前往 Ctrl/⌘ K、上下键、Enter、Escape，无结果时不跳转。
- 手机抽屉焦点约束、关闭后恢复触发器、路由切换关闭。
- TMDB 失败和空结果明确展示，不将失败当成成功的空列表。
- 375、768、1024、1440px 下主要页面无页面级横向溢出；减少动态效果设置有效。

## 非目标
本轮不新增媒体来源，不改变下载/做种行为，不增加新 Docker，不写入生产测试媒体，
不清理生产日志，不触发真实管理员恢复，不把播放器取样成功宣称为客户端解码验收。

## 浏览器验证环境
自动化回归默认使用与锁文件中 Playwright 版本匹配的独立 Chromium Headless
Shell；CI 安装相同浏览器。实际用户 Chrome 另通过已登录的工作台进行上线验收，
如需用已安装 Chrome 跑自动化，可设置 `E2E_BROWSER_CHANNEL=chrome`。
保留所有功能断言，不启用失败重试或强制点击。

## 左侧下拉导航增量（2026-10-12）
- 四个分组默认全部收起；点击或 Enter/Space 展开、收起，可分别展开多个分组。
- 当前页面所属分组只标记「当前」，不因直接访问或快速跳转自动展开。
- 桌面与手机共享本次页面内的展开状态；刷新/重新登录恢复全部收起，不写浏览器存储。
- 收起后的子项不进入 Tab 顺序或可访问树，两个导航实例使用独立的 aria-controls ID。
- 增加默认状态、键盘、刷新恢复、跨视口状态和 ID 唯一性测试；发布仍使用 Actions → Docker Hub → 服务器。
