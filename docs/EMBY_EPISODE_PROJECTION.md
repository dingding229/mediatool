# Emby 实际多集识别与非连续合集投影

日期：2026-10-11（北京时间）。源码保持迁移20；程序发布状态以emby-projection-*报告为准。

## 实际消费者发现

使用与用户部署完全相同的Emby 4.10.1.0镜像，在独立临时配置目录、内部Docker网络和自有5秒视频上建立虚构测试库。未连接外部元数据服务，去除所有虚构Provider ID，不读写用户Emby配置/密码/媒体库；仅读取扫描结果，没有调用播放/转码接口。测试结束移除临时容器、网络和账号配置。

| 原输出 | 实际Emby识别 |
|---|---|
| S01E02 + NFO | 第2集，正确 |
| S01E01-E03，有/无NFO | 第1–3集，正确 |
| S01E01E03，有/无NFO | **第1–3集，错误补出第2集** |
| S00E01 + NFO | 特殊集第1集，正确 |
| S00E01E03 + NFO | 同样错误补出特殊集第2集 |
| 只留代表首集的候选命名 | 不补中间集，但漏掉第3集，因此未采用 |

这是实际Emby消费测试，不是内部Parser round-trip或静态文档推测；不代表其他Emby版本和完整客户端矩阵。

## 当前完整覆盖策略

`AssetOutputProjections`统一用于云盘候选确认、下载入库和明确输出迁移。

- 单集仍一个STRM/NFO；连续合集仍一个S01E01-E03范围条目。
- 非连续合集为每个**已明确声明的集号**生成独立索引，例如真实集合1,3生成S01E01和S01E03，不生成E02，也不使用Emby会误扩展的E01E03链。
- 所有条目写入**同一个原固定STRM链接**，同一个assetId/文件级播放Key/云盘源文件。没有把播放地址改成Emby stream，没有转码、代理切片或伪造单集起止时间。
- **每个索引播放整个合集文件，从文件本身的起点开始，不等同单集切片或自动跳到对应集。**管理预览和NFO简介明确说明；不能在UI中声称实现了章节定位。
- 每个NFO使用该索引集号的真实单集标题、简介、日期和Provider ID，另注明原文件完整实际覆盖；不将单集播出时长当作完整文件时长写入别名NFO。
- 数据库资产绑定/media_identity始终保留原实际集合。订阅/缺集仍读取实际覆盖，不会因Emby旧范围显示而错误认为不存在的E02已下载。
- 同资产多个索引只是文件别名，不生成第二份下载/上传/做种源媒体。电影下载沿用原布局，不因本轮TV修复改变电影路径。

## 事务、恢复与原文件保护

- 所有别名STRM/NFO在一个业务事务内stage，复制同一授权内容；共享tvshow.nfo意图去重。待恢复时使用现有加密日志，不把部分别名生成当作整个任务完成。
- 字幕支持现有完整idx/sub/sup及文本侧车；每个索引复制对应同stem字幕，整组一次stage，限制500文件/64MiB总复制量，避免100个索引放大成几GiB。
- 已入库输出**不自动改名**。旧非连续链、季集变化、缺少某个别名时，“只改NFO”明确拒绝，要求用户查看输出迁移预览并确认。
- 迁移可从一个旧输出扩展到多个索引，也可从多个索引收敛到一个连续范围；只有旧STRM正文和授权引用逐字相同才可合并。不猜选不同URI/Key/同suffix不同字幕。
- 所有新STRM/NFO/字幕完成并核对后才归档旧输出；手工修改、未知归属或碰撞拒绝。旧文件按原有.retired机制保留，共享NFO和源媒体不删除。更换命名不轮换播放Key。
- Emby下载入库确认改为逐个**输出路径**计数，而不是按assetId计数。只有其中一个索引可见不完成整个导入；各Emby item/source仍映射同一个真实资产。剧集确认不使用可能匹配不到单集标题的整剧SearchTerm。

## 实际复核与证据界限

新的程序投影经同版本实际Emby复核：非连续1,3及Season 0的1,3均各得到两个独立Episode，合并覆盖精确为1,3，不补2；连续1,2,3仍一个范围条目。矩阵共有11个场景/13个Episode，包括旧错误命名的负对照，不能把负对照仍错误的结果隐去。

初次测试出现过诊断文件传输未完成及内部网络没有published port的启动问题。已以校验和传输/明确内部桥接端点复核，所有已启动临时资源按label/ownership清理；这些启动失败不是Emby命名行为证据，历史尝试报告保留。

本地PG/文件系统测试覆盖别名URI相同、绑定覆盖不变、单集NFO身份/whole-file提示、明确预览无写入、别名展开/收敛、字幕保留/冲突、旧链拒绝无迁移以及逐路径Emby确认。Vue显示同文件整体播放警告，取消预览不调用应用，375px确认按钮完整可见。

实际程序发布不自动对用户现有两个资产迁移；没有在正式数据库创建虚构影视/资源/下载/订阅记录，也不把隔离下载流程fixture当作真实PT业务完成。真实普通用户/设备解码、长seek、HTTPS、授权PT→qBittorrent→保留做种→CD2→STRM/NFO→Emby→通知和订阅验收仍保留。
