# CloudDrive2文件变化触发对账

日期：2026-10-10。源码新增迁移18；实际是否发布以部署报告为准。

## 行为和边界

- 使用项目固定的官方CloudDrive2 1.1.2 proto中的PushMessage；收到创建/修改/删除/重命名、成功挂载变化和云账号挂载变化时，只产生目录对账提示。不解析或存储日志消息、账号名称、Token、文件正文等提供方数据。
- 定时扫描配置新增watchChanges，默认false；必须同时enabled=true才会订阅/触发。不会为现有媒体库自动创建或启用扫描计划。
- 首次连接成功响应帧及重连安排一次所选范围的完整对账，因为协议没有重放游标。事件限定在配置的允许根目录和明确扫描范围，重命名检查旧/新两端及祖先目录。
- 提示以PostgreSQL中每个扫描范围的一项dirty状态持久化：首次等待10秒，后续事件不无限推迟；不为每个文件变化追加任务。当前精度为**已配置的子目录范围**，尚未实现任意变化父目录的多层增量队列。
- 调度创建扫描、扫描目录/Job及消费dirty标记共用一个数据库事务。若已有扫描进行中，保留dirty标记，等其结束后再创建一次新扫描，避免遗漏遍历进度之前的变化。
- 推送本身不改资产/文件缺失状态、不删除STRM，不替文件声明影视身份。完整扫描仍需两次缺失投票；失败、中断或扫描期间连接修订变化不能提交新的缺失投票。
- 流读取不持有数据库锁。每次最多一分钟，连接/凭据更新后旧事件回调以当前修订过滤；关闭扫描或变化开关会立即停止接收新的dirty标记并清理未消费标记。
- 断线最多一分钟后重试；不支持PushMessage时明确显示unsupported，五分钟后再检查，周期扫描继续。正常窗口轮换保留对账，不能将“连接返回200/收到初始响应”当作所有实际文件变化都已可靠送达。
- 默认协调Worker接收变化，library Worker负责执行扫描；多Worker重复观察也由dirty合并和现有扫描唯一约束避免重复副作用。

## 管理操作

在云盘索引→定时扫描配置中，先确认扫描根目录，启用扫描计划后可打开“CloudDrive2文件变化推送”。列表显示连接/等待重连/不支持/暂不可用，以及待对账提示。周期扫描间隔仍为5分钟至7天，不因推送失败而关闭。

## 只读诊断

镜像提供`/app/media-tool diagnose cloud-events -duration 5s`。读取本项目加密保存的主CloudDrive2连接，仅短时间观察PushMessage；不写事件、不创建扫描、不修改媒体。输出仅窗口、是否收到响应帧、范围内提示数量和固定结果分类，没有原始路径/凭据/提供方日志。无真实受控文件变化时realFileChangeDeliveryVerified仍false。

## 验证

自有gRPC测试覆盖认证、响应帧、CREATE/MODIFY/DELETE/RENAME、挂载变化、危险路径/未知枚举拒绝、静态Token不自动替换、回调失败/取消/连接退役、不支持/权限拒绝/断线固定分类。隔离PG测试覆盖范围/跨范围重命名、并发事件不滑动debounce、计划关闭、连接修订与根目录改变、已有扫描不吞dirty、无提示不创建任务、unsupported保留周期调度，推送不改变资产数。

真实部署、只读RPC窗口、STRM原链接/禁止转码不回退等以cloud-events-*报告为准。真实PT→下载→做种→上传→STRM/NFO→Emby→通知、订阅和客户端解码仍是独立验收门槛。
